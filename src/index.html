Démarrer

Porta[b]l Apps est un lanceur pour vos applis autonomes .html et .exe. Rien à installer, aucun réseau nécessaire : copiez le dossier où vous voulez (bureau, clé USB, dossier perso) et lancez portabl-apps.exe.

PortablApps\
├── portabl-apps.exe     le lanceur
├── portabl-apps.json    vos réglages (créé tout seul)
└── apps\                vos applis

Déposez vos applis dans apps\ (bouton 📂), revenez sur la fenêtre : elles apparaissent.

Ranger ses applis

Règle d'or : une appli = une carte. Seul le premier niveau du dossier apps\ est regardé.

Un fichier seul, à la racine

Chaque .html, .htm ou .exe posé directement dans apps\ devient une carte. Les autres fichiers sont ignorés. Idéal pour les applis tout-en-un.

Un sous-dossier = une appli

Pour une appli qui a besoin de fichiers à côté d'elle (images, scripts, DLL, données). Le fichier lancé est, dans l'ordre :

  1. celui indiqué par "entry" dans un portal.json du dossier ;
  2. sinon index.html ;
  3. sinon l'unique .exe du dossier.

Si aucune règle ne s'applique (deux exe sans portal.json, aucun index.html…), le dossier est ignoré. Les sous-sous-dossiers ne sont jamais pris pour des applis.

apps\
├── Kanban.html              ✅ carte
├── Kanban.portal.json       infos de Kanban
├── Calc.exe                 ✅ carte
├── notes.txt                ❌ ignoré
├── JsonGarage\              ✅ carte (index.html)
│   ├── index.html
│   └── portal.json
├── OutilPro\                ✅ carte (seul exe du dossier)
│   ├── OutilPro.exe
│   └── moteur.dll
├── Suite\                   ✅ carte (grâce à "entry")
│   ├── portal.json          { "entry": "Lanceur.exe" }
│   ├── Lanceur.exe
│   └── Updater.exe
└── Brouillons\              ❌ ignoré
    ├── essai1.html
    └── essai2.html

💡 Un exe qui a besoin de DLL ou de fichiers de config : mettez-le dans son propre sous-dossier. Il est toujours lancé depuis son dossier.

Décrire ses applis

Nom, description, version, catégorie, tags, couleur, icône, notes… Tout est facultatif. Les infos sont lues dans cet ordre de priorité :

1. Un fichier .portal.json

À côté d'un fichier seul : même nom + .portal.json (Kanban.html → Kanban.portal.json). Dans un sous-dossier : portal.json.

{
  "name": "Mon Appli",
  "description": "Ce qu'elle fait en une phrase",
  "version": "1.2.0",
  "author": "Moi",
  "category": "Outils",
  "tags": ["csv", "export"],
  "color": "#00f0ff",
  "icon": "🔧",
  "notes": "Raccourcis, astuces…",
  "hidden": false,
  "entry": "app.html"
}
  • icon : un emoji, ou une image à côté ("logo.png", .svg, .ico, .jpg…).
  • category : crée automatiquement un filtre en haut de l'écran.
  • hidden : true masque l'appli sans la supprimer.
  • entry : seulement pour un sous-dossier.

2. Les balises du HTML

Le <title>, le favicon et ces balises dans le <head> :

<meta name="description" content="…">
<meta name="author" content="…">
<meta name="version" content="1.2.0">
<meta name="portal:category" content="Outils">
<meta name="portal:tags" content="csv, export">
<meta name="portal:color" content="#00f0ff">
<meta name="portal:icon" content="🔧">
<meta name="portal:notes" content="…">

3. Les infos de l'exe

Description, version, société, commentaires et icône, lues dans les propriétés du fichier (clic droit › Propriétés › Détails dans l'explorateur).

À défaut de tout cela : le nom du fichier. La fiche détaillée d'une appli (ⓘ) indique d'où viennent ses infos.

Lancer et naviguer

  • Clic sur une carte : lance l'appli.
  • ☆ : favori, toujours en tête de liste. ⓘ ou clic droit : fiche détaillée (chemin, taille, notes, bouton « afficher dans l'explorateur »).
  • Filtres : tout, favoris, HTML, EXE et une pastille par catégorie. Tri : derniers lancés, plus lancés, A→Z, modifiés récemment.
  • Le compteur de chaque carte indique combien de fois l'appli a été lancée, et quand.

Réglages ⚙

  • Dossier des applis : n'importe quel dossier (local, réseau, clé USB). Chemin relatif = relatif à l'exe.
  • Thème : change l'ambiance, les textes et le son. Chaque thème a sa personnalité, prenez le temps de les explorer…
  • Ouverture des applis HTML :
    • Fenêtre dédiée (par défaut) : chaque appli s'ouvre dans sa propre fenêtre Edge, sans onglets ni barre d'adresse. Pratique pour en ouvrir plusieurs.
    • Navigateur par défaut : un onglet dans votre navigateur habituel.
    • Personnalisé : le navigateur de votre choix. {url} est remplacé par l'adresse du fichier, par ex. --app={url} pour Chrome.
  • Son : active ou coupe les sons au lancement.

Données

Tout est stocké dans portabl-apps.json, à côté de l'exe : dossier choisi, thème, favoris et compteurs. Rien n'est envoyé nulle part. Pour sauvegarder ou transférer vos réglages, copiez ce fichier ; pour repartir de zéro, supprimez-le.

Les favoris et compteurs sont liés au chemin de l'appli dans apps\ : renommer ou déplacer une appli remet son compteur à zéro.

Dépannage

Mon appli n'apparaît pas
Vérifiez qu'elle est au premier niveau de apps\ (ou dans un sous-dossier qui respecte les règles), que son extension est .html, .htm ou .exe, et qu'elle n'a pas "hidden": true. Puis F5.
Les infos de mon .portal.json sont ignorées
Le nom doit correspondre exactement (Kanban.portal.json pour Kanban.html) et le JSON doit être valide : guillemets doubles, pas de virgule après le dernier champ.
Une appli HTML s'ouvre dans un onglet au lieu d'une fenêtre
Le mode « Fenêtre dédiée » nécessite Microsoft Edge ; sans lui, le navigateur par défaut prend le relais.
Un exe ne se lance pas
Il est peut-être bloqué par la politique de sécurité du poste (SmartScreen, AppLocker), ou il lui manque des fichiers : rangez-le dans un sous-dossier avec ses dépendances.
Mes favoris et réglages ne sont pas gardés
Le dossier de l'exe est en lecture seule (ex. Program Files, partage réseau protégé). Placez le lanceur dans un dossier où vous pouvez écrire.
Le lanceur ne s'ouvre pas du tout
Il a besoin de WebView2, présent d'office sur Windows 11 et Windows 10 à jour. Sinon, l'exe a pu être bloqué au premier lancement : clic droit › Propriétés › Débloquer.
